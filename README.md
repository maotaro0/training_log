# Traininglog（ジムログ）

筋トレの記録と過去の自分との比較を通して、成長を実感するためのRuby on Railsアプリです。スマートフォンから身内で使うことを想定しています。

「記録する → 過去と比較する → 成長を実感する → 継続につなげる」を軸にしています。

## 公開先

https://training-log-v0uu.onrender.com

このブランチの変更は、マージ・デプロイ後に公開先へ反映されます。

## 使い方

1. 新規登録してログインするか、「登録せずに体験する」から試します。
2. 「記録する」で日付・種目・重量・回数を入力します。種目・セットは追加できます。重量が空欄なら自重の記録です。
3. 保存後の詳細で、前回の同じセット番号との重量・回数の差と、重量の自己ベストを確認します。
4. ホームや履歴・詳細から前回の内容をコピーし、今日の記録を作成できます。
5. 成長分析で種目・期間・指標を切り替え、グラフと日別の表を確認します。
6. マイページで表示名・プロフィール画像・月間目標を設定し、自分専用の種目を管理できます。

## 実装機能

- ユーザー登録・ログイン・ログアウト、ログイン中のパスワード変更、退会
- 複数種目・セットの記録、履歴、詳細、編集、削除
- 前回または指定した記録のコピー（日付は今日、コピー時点では未保存）
- 前回記録との重量・回数の比較、重量の自己ベスト更新表示
- 月間の記録日数と目標、連続記録日数（ストリーク）
- 共通種目と自分専用の種目の登録・編集・削除
- 種目ごとの成長分析（直近30日・90日・全期間／最大重量・総負荷量・合計回数）
- プロフィール画像（JPEG・PNG・WebP、1MB以下）と表示名
- 利用者ごとに分離されたゲストログインとサンプル記録
- スマホ向けの画面・固定ナビゲーション、入力エラー・操作結果の通知

### 集計のルール

- 月間目標とストリークは記録した「日数」です。同日の複数回の記録は1日と数えます。
- ストリークは今日または昨日までの連続日数です。未来の日付は含めません。
- 成長グラフは日ごとに集計します。重量はその日の最大値、総負荷量は重量×回数の合計です。自重セットは総負荷量に含めません。
- 詳細の前回比較は、同じ種目の直前の記録とセット番号を合わせて比較します。同日の記録は作成順で判定します。
- 自己ベスト表示は、その記録時点で過去の最大重量を超えた場合です。最初の重量記録も対象です。
- 記録に使用中の種目は削除できません。共通種目は閲覧・記録のみで、利用者からの変更はできません。

### アカウントとゲスト利用

メール送信、メール認証、パスワード再設定、問い合わせメールは設けません。**パスワードを忘れた場合は再設定できません。** 登録画面にも表示します。

ゲストの記録はログアウト時に削除します。ログアウトしない場合も24時間で利用期限が切れ、次回アクセス時または新しいゲストのログイン時に期限切れデータを削除します。定期削除する場合は `bundle exec rails guests:cleanup` を実行できます。ゲストデータの本登録への引き継ぎはありません。

プロフィール画像はデータベースに保存するため、Renderのローカルディスクには依存しません。

## 開発環境

- Ruby 3.4.12 / Rails 8.1系
- Devise、Turbo、Stimulus、Importmap、Sprockets
- Chart.js（アプリ内に配置）
- 開発・テスト：SQLite / 本番：PostgreSQL

```sh
bundle install
bin/rails db:prepare db:seed
bin/rails server
```

ブラウザで `http://localhost:3000` を開きます。種目の初期データは `db:seed` で作成します。繰り返し実行しても同じ共通種目は増えません。

## 動作確認

```sh
RAILS_ENV=test bundle exec rails db:prepare test
RAILS_ENV=test bundle exec rails test:system
```

ブラウザテストにはChromeが必要です。GitHub ActionsではSQLite・PostgreSQLでのテスト、スマホ幅のブラウザ操作、production用アセットの生成を確認します。ブラウザのスクリーンショットはActionsの成果物に保存します。

## Renderでの反映

既存のRender Web ServiceとPostgreSQLを利用します。

- Runtime：Ruby
- Build Command：`bash bin/render-build.sh`
- Start Command：`bundle exec puma -C config/puma.rb`
- Health Check Path：`/up`
- 環境変数：`RAILS_ENV=production`、`DATABASE_URL`（Render PostgreSQLの内部接続URL）、`SECRET_KEY_BASE`（`bin/rails secret` で生成）
- `BUNDLE_WITHOUT=development:test` を指定します。
- `RAILS_SERVE_STATIC_FILES=true` を指定します。
- `BASIC_AUTH_ENABLED=false` が通常の設定です。身内向けにBasic認証を併用する場合は `true` とし、`BASIC_AUTH_USER` と `BASIC_AUTH_PASSWORD` を設定します。

秘密値はGitへコミットしません。ビルドではアセット生成・マイグレーション・共通種目の初期化を行います。既存データを削除する処理はありません。旧 `training_records` のデータは新しい履歴に移行しません（今回の利用では引き継ぎ不要の方針）。

マージ後にRenderのデプロイが完了したら、ゲストログイン、記録の作成・編集・削除、グラフを確認してください。

## データ構成

`User → Workout → WorkoutRecord → WorkoutSet` でトレーニング日・種目・セットを管理します。`Exercise` は共通種目またはユーザー所有の種目、`Profile` はユーザーの表示名・月間目標・画像です。

記録・自作種目・プロフィールの操作はログインユーザーに限定しています。退会時には関連する記録とプロフィール・自作種目を削除します。

## 作成した背景

日々の変化は小さく、記録を残すだけでは成長に気づきにくいことがあります。前回の重量や回数を探す手間を減らし、グラフや比較表示を通して継続のきっかけを作ることを目指しました。

今後は実際の利用で得た意見をもとに、トレーニング中に少ない操作で記録できるよう改善します。
